# 科研选题评分与证据审查规则

版本：1.1-discussion。日期：2026-11-05。状态：讨论形成的工作规则，尚无评分引擎实现，也未校准为科研成功率预测模型。

## 1. 评估对象

评估具体问题，不直接给“LLM”“世界模型”等大方向打立项分。候选须说明：研究对象和条件、待解释现象、最近工作、拟新增知识、可证伪假设、竞争解释、最小实验、完整验证路径及资源预算。

每条主张标明身份：来源中的作者主张、来源中的实验报告、独立核验事实、系统推测、候选假设或本项目实测结果。不得相互替代。

## 2. 六维与子项

每个维度包含三个等权子项，维度分数为子项均值。

| 维度 | 默认权重 | 子项 |
| --- | --- | --- |
| 学术创新性与重要性 | 25% | 问题重要性；相对最近工作的新增知识；贡献深度与适用范围 |
| 工业问题真实性 | 15% | 具体场景和公开约束；现有方案不足；对实际工程决策的影响 |
| 研究价值可测量性 | 15% | 假设可证伪；指标有效；实验区分竞争解释的能力 |
| 个人资源可行性 | 15% | 完整验证成本；数据和代码可获得性；理解与排查核心实验的能力 |
| 企业岗位匹配 | 15% | 与具体岗位任务重合；可检查成果；可证明的个人贡献 |
| 院校导师匹配 | 15% | 与团队近期问题重合；方法与研究范式匹配；可形成的研究交流内容 |

可调整权重，总和必须为 100%。权重表达用户偏好，不代表对录用、录取或科研成功率的估计。

若六维均可评分：`TotalScore = Σ(weight_i / 100 × dimension_score_i)`，取值 1—10。不要把原始 1—10 分当作成功概率。

各维边界：工业维度评问题真实性；岗位维度评能力证明；导师维度评研究议程联系。完整研究的学习和排错成本进入可行性，不应以相同理由在多个维度重复加分。

## 3. 分数锚点与缺失值

| 分数 | 工作解释 |
| --- | --- |
| 1—3 | 有证据表明存在明显不足 |
| 4—6 | 有合理价值，但限制较大 |
| 7—8 | 比较依据充分，值得投入验证 |
| 9—10 | 需要特别强的比较依据和初步结果，谨慎使用 |
| null／待验证 | 判断依据不足 |

所有三个子项均为必评项。任一子项缺乏依据，则整维保持待验证；任一维度待验证，则完整总分保持 `null`。不得填零、填中位数、填高分，也不得对剩余子项或维度重新归一化后伪装成完整总分。

可以单独报告已评估的子项和维度覆盖率，但不能将覆盖率解释为置信度或研究价值。7 分和 8 分是依据约定所作的可复核判断，不是由某篇论文直接“证明”的客观常数。

## 4. 每条评分的记录

必须保留：原始分数、评分理由、支持证据、反对证据、证据等级、置信度、未知项、下一项核查、评估时间、评估者、规则版本与所依赖的代码／数据版本。

证据引用包含：来源 ID 和 URL、论文或网页版本、章节／表格／页码、访问日期、支持的确切判断、适用条件及不能支持的结论。

| 证据等级 | 含义 |
| --- | --- |
| A | 直接覆盖所评判断，来源、位置和条件可核验的强证据 |
| B | 明确间接证据，需要跨场景或条件推断 |
| C | 主要来自合理假设或尚未执行的设计，可作暂评，不能独立支持长期立项 |
| D | 判断依据不足，分数保持 null |

另记高／中／低置信度及理由；不将置信度直接乘入总分。来源可靠性、证据与判断的相关性、覆盖充分性需要分别检查。多处转载同一研究不算独立证据，作者报告也不等于本项目已独立复现。

## 5. 六维的证据义务

### 学术价值

制作最近工作逐项比较：解决了什么、条件是什么、未回答什么、我们新增什么、什么实验区分两者。阅读正文、附录、代码与后续工作。新颖性结论注明检索日期、检索式、来源范围、筛选标准和全文可用性；检索不到不能证明普遍不存在。

会议论文证明相应工作已被发表，不证明新的候选问题具有同等价值。新解释、测量方法和重要负面结果可有贡献，但仍须证明重要性、可靠性与增量。

### 工业真实性

分别记录企业研究兴趣、岗位技能需求与生产／工程约束。需要写出“场景 → 当前方案 → 约束 → 改善指标 → 代价 → 会改变的决策”。相关企业论文只支持其明确覆盖的判断，不能代替生产需求证据。

### 可测量性

指标须对应核心主张，区分真实机制、数据污染、评测错误、分布变化、预算差异和随机波动。计划包括合理 Baseline、阳性与阴性对照、数据隔离、不确定性分析、泛化范围和停止规则。样本量与重复次数根据精度和方差确定，不使用通用固定数量冒充充分性。

例如，数据排序变化只有在影响选择决策或最终训练收益时才有实际意义；图像干预引起回答变化，需要排除图像破坏和题意变化等解释。

### 资源可行性

当前资源上限为一张 24GB GPU，其他预算待确认。记录模型、精度、序列长度／分辨率、峰值显存、吞吐、单次耗时、存储、数据处理、评判模型或 API 成本。完整成本包含 Baseline、消融、超参数选择、重复、泛化验证、失败排查和重跑。

单次能运行不能证明完整研究可承担；缩小实验的结论范围须与目标主张一致。

### 岗位匹配

建立“具体岗位要求 → 实际项目工作 → 可检查成果 → 可独立解释和排错的个人贡献”映射。单独标注实习／正式职位、资格与地域等条件；正式岗位不能直接作为本科实习资格证据。能力相关性不等于录用概率提升已得到量化证明。

### 导师匹配

核查团队近两三年与问题直接相关的工作、具体重合点、拟新增贡献、所需基础和公开参与渠道。公开招募不代表当前名额或接受意愿。成绩、英语、招生路径和申请资格单独检查，不用学校排名替代研究匹配。

## 6. 否决审查与研究阶段

三个门槛分别记录 `pass`、`fail` 或 `unknown`：

1. 能明确说明相对现有研究的创新空间。
2. 能设计可信实验验证核心假设。
3. 完整验证资源不明显超出当前或合理可争取的条件。

未知不等于失败。若已有工作覆盖拟贡献，应停止或重定义；资源不足可进入长期候选。

| 决策阶段 | 条件 |
| --- | --- |
| 查新 | 问题具体，有意义的答案和可追踪文献入口 |
| 最小实验 | 可证伪假设、可运行 Baseline、明确小预算，尚未发现完全重复的拟贡献 |
| 长期立项 | 复现关键现象、创新审查通过、排除主要替代解释、完整资源可承担，并经人工决定 |

最小实验之后作 Go／Pivot／Stop 决策，保留依据与局限。Go 不等于证明原创、保证投稿成功或允许无限扩大资源。没有“总分超过某值就有顶会价值”的规则。

只比较同阶段候选。权重敏感性分析可在总和 100% 下小幅调整各维权重；顺序不稳定时应报告接近，并优先补证据。

## 7. 当前规则的适用限制

本规则是透明决策辅助工具，尚无历史项目数据校准。独立复核可能产生合理分歧，应记录分歧和理由。任何重要推荐都须说明什么新证据会使其降分、转向或停止。
