# 论文主线审查

主线推荐必须来自[选题状态登记](../reviews/topic-status.json)中通过检查的记录。六维评分用于比较，同一阶段的高分不能绕过升级条件。查新、试跑和主线推荐是不同决定。输出 Excel、README、聊天回复或研究报告时，先查状态登记，再使用与阶段一致的措辞。

| 状态 | 可以写什么 | 升级条件 |
| --- | --- | --- |
| `literature_audit` | 查新候选，说明待核查的拟贡献 | 比对最近邻全文，记录最强反证，冻结最小实验与停题规则 |
| `pilot_ready` | 允许做限定预算的试跑 | 用户能复核问题、指标、对照和开销。记录用 `pilot` 填写 |
| `short_project` | 短项目或学习项目 | 如发现新的、重要且可检验的贡献，重新进入查新 |
| `stopped` | 停止原切口，记录触发原因 | 有新证据时，以新问题重新查新 |
| `mainline_approved` | 推荐投入主线，明确证据覆盖范围 | 通过下列全部条件，并保留用户实际决定 |

升级前用[主线审查模板](../templates/mainline-review.json)建立 `reviews/<选题 ID>.json`，再更新状态登记。先提交 `pilot_ready` 记录和实验计划，再收集用于升级的结果。`mainline_approved` 还需填写价值、结果、资源、复现与人工决定。每次证据变更都允许降级。

1. **增量。** 记录检索日期、数据库和检索式，逐篇对照最接近工作已解决的条件和主张。直接近邻要有全文定位、剩余差异和反证。论文是否发表和期刊指标不能替代这一步。
2. **重要性。** 写出具体受影响的人、当前决策和选错的代价。提前确定决策指标、实际意义阈值及其依据。来自企业、论文和本地实验的事实与推断分别标注。
3. **结果。** 冻结最强合理基线、留出评估、预算口径和停止条件。保存本项目可复核的对照结果，注明波动、失败例和替代解释。将改进统一为越大越好。按审查前选定的不确定性下界与实际意义阈值比较。仅观察到排序变化、训练奖励提高或局部加速时，要补上最终决策代价。
4. **验证和资源。** 用另一批独立评估或复验检查结论，说明范围、总预算和复现材料。公开数据可用于初筛，外推主张必须匹配实际验证尺度。记录拟投方向及用户最终决定。

当前反例保留在状态登记。T08 的局部验题节省不足以支持主线。T14 的跨阶段排序已有直接研究，误淘汰损失尚未实测。T15 缺少修复策略的留出对照，T16 缺少等人工时间的闭环比较。

运行 `python scripts/check_mainline.py` 检查状态与证据字段，`python -m unittest discover -s tests` 验证防回退用例。GitHub 对推送和拉取请求执行同样的检查。检查能拦下缺项、无出处和未达阈值的升级记录。论文解读、实验真实性和最终价值由人工复核。
